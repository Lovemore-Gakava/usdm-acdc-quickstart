From a protocol to an executed result

CDISC's Analysis Concepts application, hosted as it stood at one commit, so you can take one endpoint of your own study from its definition to a number without installing anything. Bring a study definition and your datasets; nothing you load leaves your browser.

Open the application
Versions. The application belongs to CDISC and is under active development. This copy is fixed at commit …; a later commit may look different. The copy is rebuilt from that commit on every publish and never edited by hand. versions.json beside this page says what is served.

What to bring

  • A study definition: a USDM v4 JSON file in the shape the application's parser reads. Step 1 has a Load a study definition button; or put the file's URL in the address as ?usdm=https://…/your-study.json. The shape is documented in the set-up repository's study/usdm/README.md, with a worked definition beside it. CDISC's own sample study is on the list already.
  • Analysis datasets as SAS transport files (.xpt): the subject-level dataset and the one your endpoint reads from. Step 8 asks for them.

The eight steps

StepWhat you doWhat it establishes
1 Select StudyLoad yours, then click its cardThe protocol as data
2 Study OverviewRead the arms, visits and estimandsWhere the endpoint sits
3 EndpointChoose the concept category and the smart phrases; name the parameter and the timepointWhat is measured, when, in whom
4 AnalysisTick an analysis templateHow it is analysed
5 SummaryOne card, the endpoint in a sentenceOne declaration, end to end
6 DerivationsResolve each measure node; link its biomedical conceptHow the number is made, from which columns
7 eSAP BuilderGenerateThe analysis plan, as data
8 ExecuteInitialise WebR, upload the .xpt files, set the bindings and slices, runThe number
Step 8 has one setting that fails the run if missed. In the Resolved slices table, set the Treatment row to (no filter — keep all values). Left at a label, the engine matches one arm and stops with contrasts can be applied only to factors with 2 or more levels. The WebR engine takes about half a minute to start, and the page may freeze while it installs packages.

Worked example, with the clicks

The same path on a public simulated trial, click by click, with what every screen should show, is the quickstart README and, behind it, the book Protocol to result. Running that example needs the datasets, which are not hosted here: the README says how to set it up locally in a few minutes.

What is not here

  • Concept Reference links into the CDISC Library answer 401: they need a Library key, and a hosted page cannot carry one.
  • The sample datasets CDISC ships with the application, and any study's data. You bring yours.
  • Any server. Everything runs in your browser, including R, through WebR.
